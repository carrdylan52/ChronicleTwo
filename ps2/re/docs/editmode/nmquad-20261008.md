## Retained: the key direction reuses the stick values

The digital-key branch overrides the analog direction and then applies the
same rotation as the stick path, with the camera angle snapped to a quarter
turn. Writing it with the existing `stick_x`/`stick_y` locals instead of
separate `key_x`/`key_z` locals (and without the three unused float
declarations) gives retail's FPR assignment: `stick_y` `$f24`, `stick_x`
`$f23`, axis cosine `$f22`, axis sine `$f20`. As later webs of reused
variables, the two values are coloured after the axis locals.

The retained form keeps the stick formula's operand order
(`move_x = stick_x * axis_cos + stick_y * axis_sin`). The whole axis region
(`+0x314..+0x400`) now matches.

## Remaining: camera-query arguments and the lower corner

With the row, 63 words remain: `GetGeoCheckCamCol`'s `a0`/`a1` setup at
`+0xB68/+0xB70` and the ground query from `+0xD2C`.

- Passing a real `mgVu0FBOX box` (`box.max`/`box.min`, `GetGeoCheckCamCol(map,
  box, ...)`) restores retail's argument order exactly (`move a0,s2`,
  `addiu v0,sp,404`, `addiu a1,sp,400`, `a2`, `a3`). In the cast form the box
  address is shared with the earlier `box_max[...]` accesses and set up first.
  Un-nesting the call, `(CMap *) map` and `> -1` do not move it.
- Retail holds the lower-corner pointer (`sp+416`) in `s5` from `+0x77C`
  through `+0xDA8`: the first copy, the three `[0]` adjustments, the
  `mgVectorMaxMin` argument and the ground-query copy. Only `[1]`/`[2]` use
  fresh `sp+420`/`sp+424` addresses. MWCC propagates a pointer with a single
  definition from a local's address into every use and rematerialises it
  (`addiu v0,sp,416`), whether the definition is a declaration initialiser,
  `&box.min[0]`, `float *const`, or an embedded assignment. The draft's
  second assignment at the ground query blocks propagation but creates a
  separate web (`t2`), so `s5` falls to the ground count.

No float-pointer local exists elsewhere in the function, so a reused pointer
variable cannot explain retail's non-propagated single web. A typed-box
candidate needs a source form that keeps the min-corner address in one
callee-saved web without a second visible definition.

## Why the single lower-corner web is lost

Toy compiles (`.private/nmquad/toy/p1..p4`) show that MWCC keeps a
single-definition pointer to a local array in a saved register across
calls, however long the range; it does not propagate it at IR level. A
separate `p = b;` statement is forward-substituted within its basic block,
while an embedded `(p = b)` is not; a web that crosses no call is
rematerialised. In EditMode the single web (`+0x77C..+0xDA8`) is therefore
a register-allocation spill: with it, `poly_count` and the ground count take
`s5`, and every use rematerialises `sp+416`. Retail colours the same web
`s5` and gives `poly_count` `s6` and the ground count `s4`; only six saved
registers are live across the camera block, so retail's choice is the
simplify order (degree below 25 before the node becomes a spill
candidate), not a register shortage.

New single-web probes, all `0x1DEC` with the row unless noted:

| Change on the single-web form | Row |
|---|---:|
| `box_low` declared before the box, after `move_info`, before `maps`, before `old_pos`, or after `new_pos` | `0x1DEC` |
| Ground count initialised before the loop, in the `for`, at function scope; `next_poly` moved; both swapped | `0x1DEC` |
| `added` declared before the loop; a fresh block-scoped map index | `0x1DEC` |
| Redundant declaration initialiser plus the embedded assignment | `0x1DEC` |
| `register float *box_low` | `0x1DEC` |
| Camera block: un-nested `GetGeoCheckCamCol` result, conditional height, swapped `camera_hit`/`camera_dir`, `wall_parts &&` | `0x1DEC` |
| Direct `scene->GetMap`/`GetCamera` calls instead of the wrappers (either or both) | `0x1DEC` |
| Typed box with the second assignment moved before the `wall_parts` test | `0x1DEC` |

A redundant `box_low = box_min;` statement placed just before the
`wall_parts` camera override (cast-box draft) gives **14/1912** with the
row: the ground-query corner then lives in a saved register (`s4`), with a
new `addiu s4,sp,416` in the delay slot at `+0xC5C` where retail has `nop`,
and `s4`/`s5` exchanged with the ground count and map offset. The same
statement before the `ePartsCurPos` copy or after `GetEditAngle` gives 66,
before the limit-height query 106. That statement has no source meaning
beyond code generation and is not retained; it shows that retail's corner
pointer is one web that survives the camera block. With the direct scene
calls it gives 131-199.
