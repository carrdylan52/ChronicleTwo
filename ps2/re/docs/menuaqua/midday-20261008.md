# Aquarium guarded drafts at the October 8 midday base

The base is `fe60604`, including upstream `d8bf13c`. Measurements below use
MWCC 3.0-011126 through the checked-in Satan's Fiddle adapter and profile in
`chronicletwo_dev:sf-d8bf13c`, with `UNMATCHING` and `NONMATCHING` defined.
The plain-wibo draft helper does not apply that profile and is not the basis
for these results. Previous negative experiments in `notes.md` and the shared
[constructor investigation](../funcpoint/placement-new.md) remain applicable.

No function is promoted. The complete canonical object continues to pass
`0x11C3C` allocated bytes and 3,244 resolved relocations, because each of the
four drafts retains its retail fallback. All 120 previously exact functions
remain exact in the final native draft comparison.

## DrawFishParam rectangle lifetimes

The function draws the selected fish's panel: a two-pass tiled background,
name and sex labels, kind and five parameter cells, size and weight cells,
then the name with the menu font. Existing `BREEDFISH_USED` fields and table
types already describe those accesses; no additional field layout is needed.

The m2c output exposes two persistent `mgRect<int>` values at stack offsets
`0x280` and `0x290`, the `CMenuFont` at `0x2A0`, and fifteen single-use
rectangle argument slots from `0x360` through `0x440`. Each rectangle is
four integers, size `0x10`. The background destination/source occupy
`0x360`/`0x370`; later slots belong to the name board, sex mark, parameter
board and kind/icon, size board/unit, weight board/unit/label, and the three
unknown-weight glyphs. The retail frame is `0x450` bytes.

The retained draft constructs single-use rectangle arguments at their calls,
keeps the reused label and digit rectangles as locals, and scopes the six-cell
index to its loop. This restores the `0x450` frame and the retail rectangle
and font slots; the original draft used a `0x430` frame and reused a rectangle
for all three unknown-weight glyphs. The existing `MG_PRIM_SPRITE` enum names
both primitive batches. The native extent remains `0xAA4`, so correct stack
slots alone are insufficient for promotion.

The first unresolved scheduling window reads the six width/height edge
bytes: retail reads them before copying the two initializer templates, while
the current aggregate expressions interleave the reads and template copies.
Background loop register roles and later integer/float argument preparation
also differ. Reconsider source that explains this ordering and the remaining
extent difference together; do not infer a match from stack layout alone.

## SettingAqua float scheduling and construction

`SettingAqua` replaces the active tank's scene resources, loads its fish,
configures bubble systems and water, and constructs the pairing effect's
plain `CCharacter2`. The pinned profile baseline is 16/752, not the older
2-word measurement in `notes.md`.

Fourteen differences belong to evaluation of 47.0f in bubble initialization
near `+0xDC` and the water's `SetPosition(-34.0f, 47.0f, -21.5f)` near
`+0x638`. The private profile adds one real-expression selector:

```json
{
  "translation_unit": "menuaqua.cpp",
  "function": "SettingAqua__9CAquariumFv",
  "value_type": "binary32",
  "value_bits": "0x423c0000",
  "evaluate_first": true
}
```

`setting47` measures 2/752 with this row and leaves the other 120 exact
functions exact. Its only remaining words are the allocation guard at
`+0xA00`/`+0xA04`: retail branches on `v0` then copies the result in the delay
slot; native copies first and branches on the saved register. The native
extent is `0xBB4`, against the retail `0xBC0` padded extent.

The row remains private, since the constructor is not resolved and it cannot
support an accepted promotion. The existing `CCharacter2` chain has no
evidenced homogeneous member array whose initialization would naturally
change the compiler's constructor classification. Do not introduce one or
steer the guard with a helper. Reconsider after a natural shared-constructor
fix becomes available, then remeasure this exact selector with the whole unit.

## Step switch recovery and later scheduling

`Step` runs the pairing transition, aquarium menu state machine, mode-change
window setup, food and effect updates, and per-fish simulation. It dispatches
food consumption, sex-change and death messages from the simulation's result
bits before stepping the message windows. Its already documented types and
fields are unchanged.

The original m2c pass did not recognize the two tables as jump tables. An
analysis-only reader shim aliases the existing symbols `at_4299` and
`at_4300` to names with m2c's required `jtbl_` prefix and resolves the existing
function-plus-offset table entries to their actual branch labels. Running
`decompile.sh` with the original data files then recovers the complete
18-entry mode switch and six-entry menu dispatch. The shim changes names in
memory only: no assembly file, instruction or table payload is written.

The first instruction-count shift is around `+0x664`: native uses the tank
index shift in a branch delay slot where retail has a nop, and schedules the
cursor and table indexing differently. Realigning only for diagnosis exposes
additional windows near `+0x11B0` (question cursor/food table), `+0x1374`
(pairing selection), and `+0x17F0` through `+0x1AB4` (simulation result/index
register roles). A later native nop around retail `+0x1740` cancels the
earlier one-word shift. These later windows must be addressed separately;
the first table expression is not the entire blocker.
