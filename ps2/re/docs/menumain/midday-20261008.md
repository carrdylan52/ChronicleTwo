# MenuMainInit constructor boundaries at the October 8 midday base

At `fe60604`, with the pinned `chronicletwo_dev:sf-d8bf13c` image and checked-in
Satan's Fiddle profile, `MenuMainInit__FP13MENU_INIT_ARG` remains guarded.
The native comparison is 792/948 differing words, `0xEB4` native bytes against
the `0xED0` retail extent at `0x235060`. All other 52 native functions compare
exactly. The canonical whole object passes `0x4F98` allocated bytes and 1,396
resolved relocations.

The function initializes the main-menu work areas, camera and drawing
environment, shared key state and message objects, restores game/save-data
references, and selects the initial menu flow from `MENU_INIT_ARG::open_type`.
Its mode values and dependency layouts are already documented in `notes.md`
and the headers; no new owned type definition is needed.

## First allocation guard

The `MENU_DRAW_ENV` construction at `+0xBC`/`+0xC0` is the first differing
allocation guard: retail tests `v0` and copies it to `s1` in the delay slot,
while native copies first and tests `s1`. The existing typed constructor
already constructs the camera with 8.0f. Neither a missing camera constructor
nor an additional float selector explains these two words.

The [placement-new investigation](../funcpoint/placement-new.md) identifies
the constructor classification involved. There is no evidenced initialization
array in this constructor that can supply a natural statement-shaped inline
body. Inventing one, changing a member's layout or adding a helper would not
be a supported source reconstruction. This remains the first blocker.

## Shared key-state rectangle initialization

The existing `menusys/notes.md` construction observation is confirmed against
the recovered `MenuMainInit` sequence. `CMenuKeyFunc`, size `0x160`, initializes
its `mgRect<int>` member at `+0x90` with `Set(0, 0, 0, 0)` before constructing
the `CGameDataUsed` member at `+0xC0`. It then sets `have_swap` at `+0x12C` and
calls `Initialize`. The current header's `mgRect` default constructor is empty,
so the `CMenuKeyFunc` initializer list does not emit this rectangle call.

The exact proposed ownership-external correction is saved as
`.private/proposals/menusys-menu-key-rect.patch`:

```diff
-    CMenuKeyFunc() {
+    CMenuKeyFunc() : rect(0, 0, 0, 0) {
```

This is a local member initializer, not a proposal to change every `mgRect`
default construction. The real shared header is untouched. A private include
overlay containing this one change restores the observed member construction
order, but measures 816/948 positional differences with a `0xECC` native
extent. Construction still has extra allocation-result copies and downstream
scheduling differences. The smaller extent gap is not sufficient evidence
for integration; the proposal needs the owning lane's whole-object validation
and the constructor fix before it can support a promotion. The best current
score remains the unchanged 792/948 baseline.

## Switch recovery and receipts

`decompile.sh` initially could not identify the open-type jump table. The
analysis-only shim described in `menuaqua/midday-20261008.md` aliases the
existing `at_1440__2` table and resolves its existing function-relative entries
to actual labels in memory. The complete pass then recovers the switch and
its initialization paths. No assembly file or instruction is written.

Receipts under `.private/mapaqua-midday/` are `baseline-menumain/`,
`m2c-MenuMainInit.log`, `m2c-MenuMainInit-tables.log`, and
`menumain_rect_overlay/`. The overlay replaces the include search root with
private symlinks and the copied proposed `menusys.hpp`, so that measurement
actually uses the proposal. It is diagnostic, not a canonical acceptance
build. No `menumain` source, owned header or profile row is changed.

The final full build retains only the baseline PAL `.text` discrepancy of
`0x26` bytes. `final-objects.log` and `final-hash-comparison.json` record the
canonical object result and comparison of allocated bytes across all units;
`final-coverage.log` retains 6,736 matched / 124 guarded / 10 asm-only / 2
fuzzy functions. These files are under the same private receipt directory.
