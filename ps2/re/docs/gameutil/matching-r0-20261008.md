## Natural source and register reuse

The useful declaration order is `next`, `frame`, `vertex`, `driven`, `key`,
`vertices`, with the vertex-specific locals declared in the function's existing
declaration block and assigned only in the vertex case. `vertex` is unsigned.
All six variables have real roles; no dummy variable, helper, raw pointer
arithmetic, assembly, explicit register annotation or pragma is added.

The resulting allocation uses `s1` for next, `s2` for the resolved frame,
`s3` for camera and `s4` for key. In the vertex case, the frame's dead register
is reused for the vertex index, the camera's for the driven frame, and the
root's `s5` for the vertex-array pointer. This accounts for the observed
register reuse without manual assignments to machine registers.

Replacing the inherited `count + (key - next)` expression with `count - 1`
is exact when the later vertex-index expression converts `list->target` to
unsigned before subtraction. Retail's clamp emits `li v0,-1`, then computes
next, then `addu v0,t0,v0`. The signed target-subtraction form instead emits
an immediate count decrement and shifts later code by one word. This is a
measured cross-expression compiler sensitivity; these experiments do not
identify its internal compiler mechanism.
