## Temporary-scene initializer

`MenuItemCharaDataLoadEndCheckAfter__FPP17MENU_BGREAD_INFO2i`
remains **2/220** words. It constructs an actual local `CScene`, not
an allocated scene. Its model-list member receives `sp + 0x2440`
(`CScene` at `sp + 0x70`, member at `+0x23D0`). The draft sets this
address in `a0` at `+0xF4`, the preceding message-loop branch's delay
slot; retail uses a `nop` there and sets the address at `+0xFC`, in
the `CMdsListSet::Initialize` call's delay slot.

`CCharacter2` is derived from `CActionChara`; changing the local pointer
to that base does not change these instructions. The robot-parts query
and scene unit setup keep their existing GLOBAL bindings, so there is
no supported static-linkage correction or shared-header proposal.

## EnterDataMenu palette access

`EnterDataMenu__15CMenuChrCngMenuFPUc` has an indexed palette draft
of **`0x620` bytes**, exceeding retail's `0x610` comparison extent.
An extent failure has no meaningful fixed-extent word score. Earlier
11-word results depended on an unsafe pointer walk and do not describe
this current source. The existing allocation-result scheduling residual
also remains documented in the earlier notes.

The new byte forms access the palette's byte representation through
an integer index. They do not advance a pointer. The new typed-colour
forms retain the four-byte RGBA array type and index each entry.
