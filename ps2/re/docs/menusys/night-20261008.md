## CommonSetMoveItemClass — promoted

`CommonSetMoveItemClass__FPA4_i` matches (0/248, raw `0x3D8` = retail symbol
size 984) and the whole unit passes. Two source facts close the 42 words:

- The four input integers are copied into `MENU_ITEM_MOVE_INFO::from` by a
  four-iteration loop over `table[i][j]`. MWCC unrolls it completely; the first
  iteration keeps its index-zero address as `addu a1,a0,$0` before `lh a1,0(a1)`,
  which is the retail "row-pointer copy". The same unrolled-first-iteration
  `addu rd,rs,$0` appears in the matched `GetCharaMemAllocSize` (charasetup)
  seven-column sum. Four explicit assignments, a loop over the named `slot`
  pointer (`move->from[j] = slot[j]`), or a loop over `table[i][j]` while
  `slot` is already live fold the zero offset and lose the copy.
- The named row pointer `int *slot = table[i]` is declared after the copy loop.
  Removing it (indexing `table[i][k]` everywhere) makes MWCC strength-reduce
  `&table[i][1]`/`&table[i][3]` into extra pointer temporaries.
- The list test is `move->from[2] == 0`. With `!move->from[2]` MWCC keeps a
  `dsll32`/`dsra32` re-sign-extension before the later `== 1` test; with the
  explicit comparison the retail `nop` remains instead.

## MenuDataSwap — promoted

`MenuDataSwap__FP13CGameDataUsedP13CGameDataUsedi` matches (0/228, raw
`0x38C` = retail symbol size 908) and the whole unit passes. Retail's tail is
`static s8 ret_tbl1[2] = {1, 3}` (LOCAL `ret_tbl1$2511`) plus a local
two-byte array initialized from the compiler template `@2512 = {0, 2}`.
Following the unit's existing `at_NNNN` convention (`KeyPairTable key_mask =
at_2328`), the template is now the struct `MenuSwapResultTable at_2512` and
the tail copies it by value. Three source facts close the residual:

- The template is copied by aggregate initialization/struct assignment, which
  MWCC lowers to retail's `lh`/`sh` pair; separate element stores (the old
  draft) give byte stores.
- The source-presence lookup is evaluated into `result` before the copy:
  `result = ret_tbl1_2511[had_src]; MenuSwapResultTable results = at_2512;
  results.v[0] = result;`. Retail's register reuse (`v1` for the table address,
  then the template halfword) shows the lookup precedes the copy in the IR.
  A separate single-use local (`s8`/`int empty_result`) is sunk below the copy
  (36), as is a dynamic initializer `{ret_tbl1[had_src], 2}` (36); the
  struct copy with separate stores gives 36; reusing `result` gives 4.
- The destination flag is declared first (`int had_dst = 0; int had_src =
  0;`), giving `had_dst` s0 and `had_src` s1 (4 → 0). Function-scope flags
  grow the body to `0x398`; split declaration/assignment at block scope keeps
  4 with the source flag first and 0 with the destination flag first.

A natural function-local `static` table plus local array initializer gives the
same instructions, but MWCC names them `ret_tbl1$NNNN`/`@NNNN` with this
build's counter (1823 here, 2511 in retail), so the existing C++ data
definitions and the struct-copy convention are retained.
