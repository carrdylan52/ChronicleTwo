## Round 1 (nminv): DngTreeMapInit and ClsMes::Init promoted

Base `9a6519fc`, same image and settings. Receipts are under
`.private/nminv-r1/` (`probes/dngmenu/`, `receipts/`, `ledger.jsonl`).

`DngTreeMapInit__FP9mgCMemoryPiii` is now exact (0x3F8 bytes, GLOBAL, in
the 0x400 reservation). Two source corrections close its 55 words:

- **Opening modes are a switch.** Retail tests `li v0,3; beq s6,v0,sep;
  beqz s6,sep; b default`, an unoptimized two-target chain followed by an
  unconditional branch to the common-menu block. `if (mode == 3 || mode == 0)`
  inverts the last test (`bnez`), and every boolean form normalizes with
  xori/sltiu. `switch (menu_mode) { case 0: case 3: ... break; default: ... }`
  emits retail's chain exactly. MWCC compares the labels in reverse order:
  `case 3: case 0:` tests zero first. The values are `MenuOpenType`
  (`MENU_OPEN_MAIN_TOWN` from the world map, `MENU_OPEN_DNG_TREE_MAP` from
  the tree-map request; the in-dungeon main menu supplies its own type).
- **The cursor buffer is a byte image pointer.** Retail stores
  `MenuCursorDataBuff` and reloads it for `LoadFileMenu` because the global
  is not `u_long128 *`: storing a converted `stGetTop()` result and passing
  `(u_long128 *) MenuCursorDataBuff` produces the store/reload pair. Its only
  other consumer, `CMenuTreeMap::InitEnd`, passes it to
  `EnterIMGFile(u_char *)`, so `u8 *` removes that cast. `void *` and
  `char *` also match; `u8 *` is retained for the IMG consumer. The earlier
  byte/void-global probes (71 words) combined these types with the boolean
  condition; with the switch they are exact. An assignment inside the
  loader argument does not reload.

With the native tree initialization, the inline constructor emits
`Init__6ClsMesFv` (retail binding 13) from the unchanged shared header, so
its assembly marker is removed. The complete dngmenu object passes
(0x8BB0 bytes, 1,214 relocations), all 149 objects pass, and
`SCES_511.90: OK` (6,756 perfect).

Diagnostics show MWCC schedules the first-line X chain before the height
load whenever height feeds only Y: height loads first only when it also
feeds X (`(W >> 2) - (H >> 1)`), when Y is stored first, or when the save
label is stored first. Within the X expression native code always loads the
`message`-relative line width before the global width, unless the width is
a separately assigned local. Retail's order (height, width, line width)
therefore needs both a different X evaluation order and an earlier Y
dependency; no natural form found supplies the second.

## Round 1 (nminv): DrawGeoramaMateria

`DrawGeoramaMateria__FiPciPii` stays guarded (baseline `0x404` against 0x400).
Retail's loop selects the column with two arms that each shift the item
width and subtract it from their own column; the width is loaded once before
`index % 2` is evaluated. Its else arm reloads the spilled right column
(`lw v0,0xA0(sp)`) and shifts into `v1`, so the delay-slot filler can copy
that shift into the `bnez` slot. Retail also places the item and title width
outputs above their heights (`sp+0x1CC`/`0x1C8`, `0x1C4`/`0x1C0`).

| Form | Result |
|---|---|
| `int item_h, item_w;` and `int text_h, text_w;` | `0x404`; both width/height slot pairs now match retail |
| If/else arms `x = column_left/right - (item_w >> 1)` | `0x40C`; each arm reloads the width |
| Same with `int w = item_w;` before the test | `0x40C`; retail's loop shape, but the right column stays in a saved register, so the delay slot is not filled |
| Conditional expression with both subtractions | `0x40C` |
| `SetPos` called in each arm | `0x41C` |
| `if (name != NULL) { ... }` instead of `continue` | `0x40C` (same as the `continue` form) |
| Column variables declared before `left` | `0x40C`; `left` still spilled |

Every form spills `left` (five uses outside the loop) and keeps both
columns in saved registers. Retail keeps `left` in `s5` and spills
`column_right` (one use inside the loop). That spill choice alone accounts
for the unfilled delay slot, the early `left + 0x186`/`top_y + 0xEF`
setup before `sprintf`, and the remaining register roles. No natural
source change found moves MWCC's spill choice; a retry needs evidence of
what changes the relative spill costs.

## Round 1 (nminv): DrawGeoramaMateria promoted

`DrawGeoramaMateria__FiPciPii` is native and exact (0x400, all 256 words).
The deciding change is that one `x`/`y` pair, declared with `index` at the
top of the function, holds every text position: the title, each list row
and the page counter. With separate per-draw expressions the panel-left
position looks cheaper to spill; once the shared `x` and `y` are reassigned
across the whole function, MWCC spills `column_right` (`sp+0xA0`) like
retail, which fills the column-branch delay slot and moves the page-position
setup ahead of `sprintf`.

The list body reads the item width into `x` before the parity test, and
each arm turns it into the column-centred position:

```cpp
x = item_w;
if (index % 2 == 0) {
    x = column_left - (x >> 1);
} else {
    x = column_right - (x >> 1);
}
font.SetPos(x, y);
```

## Round 1 (nminv): DrawRoomOne promoted

`DrawRoomOne__11CDngFreeMapF9mgRect_f_P16DNGMAP_ROOM_INFOUiif` is native and
exact (0x914 bytes of code, all 584 words with retail's three padding
words). Several independent source forms were needed; each one is shown
against the form before it.

- **Glyph table indexing.** Retail keeps one `i * 4` induction for the
  glyph loop and forms the glyph-table offset as `(i * 4) << 1`. It also
  keeps `&w`/`&h` of the current glyph in `s6`/`s7`. Reading
  `get_moji_tbl_1524` as a flat `s16` table indexed `[i << 2]`,
  `[(i << 2) + 1]`, ... produces that shape, as in the matched
  `Menu3DivideTextureDraw` in menudraw. A `RoomGlyph` pointer, a struct
  array, a 2-D `s16 [][4]` array and flat `[i * 4 + k]` indexing all fold
  to a separate `i * 8` induction. The extra induction then forces
  `opacity` out of `s8` onto the stack and leaves `&picture.top` in `s8`;
  retail rematerialises it at every use instead.
- **`tex_no` local before the visited test.** `int tex_no = room->tex_no;`
  ahead of `if (room->visited == 0)` lets the delay-slot filler move the
  `lb` into the `bnez` slot, and issues the `% 5` divide first. Column and
  row are computed from it into locals before either store; the special-room
  path still reads `room->tex_no`.
- **Colour components.** Separate `r`, `g`, `b` initialised to 192 and
  assigned `b = g = r = value`, so `r` is written first like retail.
  `r = g = b = value` reverses the three copies (4/584).
- **Overlay.** Explicit `fptosi` calls interleaved with the two float bases
  (`left`, `top`, then `right`, `bottom`).
- **Other forms.** The shadow alpha is a float local computed after `level`
  and converted at its use. `tint = 128.0f * event_brightness` is computed
  before the glyph test and converted inside the loop. Mark rectangles are
  stored with direct `mark_rect[mark_num]` indexing followed by
  `mark_num++`. The sub/boss test is two `||` flag tests, and the
  third-row texture height uses an `if` after the plain assignment.
