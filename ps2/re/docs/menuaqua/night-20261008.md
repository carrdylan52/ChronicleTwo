## ColCheck fish lifetime

Testing the actual `fish[no]` slot for null before assigning the selected
fish to `me` resolves the previous exchange of `s2` and `s3`. MWCC eliminates
the redundant slot load and keeps the selected fish in retail's `s3`.
The two source accesses therefore produce one machine load at function
offset `+0x44`. This is a real null check followed by a binding, without
an added object, artificial dependency, or compiler-profile override.

The draft improves from 60/448 differing words to **0/448**. Its native
symbol size is `0x6F8`, agreeing with retail's 1,784-byte symbol; the manifest
extent includes eight zero padding bytes. A private activation compiled
through `mwccgap.sh` and `fixup_sections.sh` passes the complete unit:
`0x11C34` allocated bytes and 3,248 resolved relocations.

**The function remains guarded.** Its inherited obstacle loop still advances
`point++` over an array. That source violates this lane's pointer-induction
rule even though its instructions match. An indexed replacement must also
match before promotion. The retained change improves the fish binding only.

## Round 1 (nminv): DrawFishParam promoted

`DrawFishParam__FiiP10mgCTextureP13CGameDataUsed` is native and exact. Its
code is 0xAF8 bytes; retail's 0xB00 symbol includes the two alignment `nop`s
that the complete object also emits. Complete-unit check: menuaqua object
`0x11C2C` bytes, 3,263 relocations; 149/149 objects pass; SCES_511.90 OK
with 6,758 perfect functions.

The retail panel code follows one layout style throughout, and each
difference from the earlier draft traced back to it:

- **Float-to-int conversions are casts, not explicit `fptosi` calls.**
  MWCC can CSE a repeated `(int) (fy + cy)` cast. Retail does this for the
  size and weight boards (`move s3,v0; move s1,v0` after one conversion) and
  for the name board / name `y` (`move a2,v0` plus the `name_y` spill).
  Under the unit's 0x30 helper mask, the 69.0 temporary before the
  unknown-weight conversion takes `a2` instead of `a0`. In the background
  loop, casts are evaluated left to right (x first, kept in `s3`); explicit
  calls go right to left.
- **Cell positions use the running `cx`/`cy` offsets.** After the parameter
  cells, `cx = 0x16; cy += 0x16;` positions the size board, and
  `cx += 0x8A` positions the weight board. With `fx + cx`, MWCC keeps
  retail's `fx`-first `add.s` operand order and recomputes `fx + cx` at
  each use. With the literal `fx + 160.0f`, it puts the constant first and
  CSEs the sum into `f22`.
- **Shared `bx`/`by` positions.** The size board, weight board, weight-unit
  label and unknown-weight glyphs all reuse `bx` (`s2`).
  `int wy = by + 2;` is declared before the weight board call, so the label
  row lands in retail's `s3`. `by += 2` instead rematerialises `by + 2` at
  each use.
- **Size digits are computed before drawing**: `size_high`/`size_low` read
  `breed->size` once, issuing the `div` early and keeping the remainder in
  `s4`.
- **Weight-unit and label rectangles index `get_paraxtbl_2494[lang][8]` and
  `[7]` directly**, so `lang * 60` stays in a register and each field address
  is rebuilt (`lui`/`addiu` + offset). The known-weight flag is read as
  `data->data.fish.flags`, a reload from the spilled `data` parameter.
- **Centre spans first.** `center_w`/`center_h` are computed from the six
  edge bytes before the `w[5]`/`h[5]` initializers, with `fx = x; fy = y;`
  ahead of them. This reproduces retail's six early `lbu`s and the template
  copy order (the first unresolved window in `midday-20261008.md`).
- **`item_no > 1`** gives retail's `slti at` branch form (`>= 2` computes
  into `v0`).
- **Loop initializers** are `cy = 0, row = 0` and `cx = 0, col = 0`.
- **`poffset_2511` is declared `s8 [8]`** (one byte per `LanguageCodeNo`).
  The incomplete `[]` declaration prevented gp-relative addressing of this
  8-byte `.sdata` table.
- **The label row `24.0f + fy` is written at each use** instead of a
  `label_y` local. The repeated float expression is CSE'd into `f20`, and the
  name-label address is scheduled ahead of the constant as in retail.

## Round 1 (nminv): CAquarium::Step

`Step__9CAquariumFv` improves from 1111/1732 to **39/1732** (both `0x1B04`).
The retained draft reads the menu-id table as a flat `s8[18]`:

```cpp
switch (menu_id_tbl_3721[aqua_no * 6 + menu->menu_cursor]) {
```

With the 2-D `[aqua_no][menu->menu_cursor]` form, MWCC computes the row
before loading `menu_cursor` into `v0`. The fall-through filler then moves
the first shift into the `+0x664` delay slot, which shifts every later word
until a compensating nop at `+0x1740`. The flat form loads `menu_cursor`
into `a0` first, as retail does. The delay slot stays empty and both
structural differences disappear.

Retail still adds `cursor + (table + tank * 6)`, the 2-D association, while
the flat form adds `(table + cursor) + tank * 6`. Writing the subscripts
commuted (`cursor[row]`, compiled only as a diagnostic) produces the same
object as the 2-D form: MWCC canonicalises the operand order, so retail's
column-first evaluation is not reachable through source operand order. Both
`another_aquarium_Notbl_3642[tank][question_cursor]` lookups show the same
pattern: identical instructions, but retail colours the cursor `a1`/`a3` and
the table `v0`/`a0`, consistent with the column being generated first.
