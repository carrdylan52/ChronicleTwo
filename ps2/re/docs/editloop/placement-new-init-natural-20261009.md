## Hygiene, types and exact blockers

The selected float-vector type-pun is replaced by
`memcpy(position, initial_position, sizeof(position))`, preserving the actual
16-byte extent. **Equal score and size do not mean equal selected code.**
The compiler emits a five-instruction memcpy call instead of the
five-instruction inline vector copy, changing five masked words and adding
a call relocation. Explicit pairwise receipts preserve both forms. An early
status incorrectly inferred equality from the score; that inference was
corrected before freezing.

Current implicit `CameraCtrlParam` assignment expands the ten float fields
and one integer into EditInit. Retail instead calls the generated
`__as__15CameraCtrlParamFRC15CameraCtrlParam` member. The ten-float-plus-int
0x2C layout is established by existing methods and the isolated natural
assignment note. No field array or manual replacement member was invented.
The best direct-call multisets differ by that missing assignment call and
the added memcpy call. Header declaration switches that would substitute a
user-provided assignment, artificial emission sites and repeated depth
changes were not used.

The 0x320 frame and real local extents remain unchanged: INIT_LOOP_ARG is
0x50; NowLoadingInfo 0x3C; mgCMDTBuilder 0x90; mgLoadData 0x40; mgCFrameAttr
0x90; the image filename is char[64]; each MapJumpMapInfo is 0x18; material
and position are real 16-byte vectors. Chest, effect, camera and action
character sizes are respectively 0x680, 0x1190, 0x1F0 and 0x1030, with
genuine allocation/count arithmetic and the real eight-element action array.
File format casts interpret actual loaded MDS/IMG/pack buffers; other pointer
arithmetic indexes the real quadword scratch buffers or typed arrays. No
field byte arithmetic, padding local, type-pun, LIT alias, assembly or manual
vtable operation was added to the selected candidate.

The existing `fishing_item` is still unassigned. Retail saves incoming s4,
then writes it only at +0x1B04 and +0x1B20 to EdDebugInfo rod/bait fields,
before restoring it at +0x1B9C. Fresh m2c identifies `saved_reg_s4`, and the
compiler continues to warn that the source local is uninitialized; the
native stores use s2. SubGameInfo's documented constructor also leaves rod
and bait uninitialized. Neither this nor the BSS allocation proves a fishing
item default. No new initialization, copied unknown state or arbitrary
register lifetime was introduced. This remains an honest source-purpose
blocker in addition to the assignment and vector-copy differences.

The best positional relocation maps differ at 574 offsets. A separately
labeled heuristic alignment matches 1726 masked instruction tokens and
reports 34 residual blocks; it ignores relocation identities and branch
destinations and is not a matching score or retail-target audit. Other
residuals include BGM/menu scheduling and field stores. No full selected
