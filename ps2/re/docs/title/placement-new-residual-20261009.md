# Natural title boot construction residual

`TitleBootInit__Fv` remains guarded. Fresh pn15 control is 56 words different;
its exact one-site CActionChara after-inline row leaves 54. Full source
hygiene and genuine value/lifetime changes reduce the best measured result
to 19 words, in the actual LOCAL/FUNC 0xa84 body within extent 0xa90. Five
relocation offset/type entries still differ in the menu-argument region.
The result is not a complete object or linked PAL match.

The remaining words are two map-top call/save differences at +0x180/+0x188,
ten icon-loop differences at +0x520..+0x590 and seven menu-argument scheduling
differences at +0x730..+0x750. No validated float capability selects these
pointer/integer values. The private profile includes only the actual
CActionChara constructor and the actual follow-camera positive-zero argument,
each with expected/actual count one. The zero row fixes all six camera
argument words. Existing title drawing rows and helper masks are preserved.

Fresh m2c and existing title/dependency notes establish the movie/card/camera
and sound allocations, scene/map memory, title image and save-icon loads,
native action-character construction, event sound, read buffer and final
boot mode choice. Only the class-6 CActionChara root is eligible. Movie
construction is trivial; the card manager, cameras and wave-table constructors
remain out of line. Local scene/map/sound-memory construction is retained.

Retail uses two distinct signed file-size output objects, at sp+0x2dc for
the first image and sp+0x2d8 for later loads. Explicit unsigned conversions
retain the allocator's logical rounding shifts without the inherited int/u32
pointer pun. Declaring the longer-lived size before the first-image size
matches their stack positions. Real map-number/map-buffer bindings, grouped
sky stores and read-buffer size/top bindings account for further measured
improvements. Values still reload after callbacks. Icon sizes are read after
GetPackFile and data/size reload after allocation, as retail does.

Known layouts remain unchanged: memory 0x30 with stack/used/size at
+0x20/+0x24/+0x28; icon record 0x28 with data/count +0x20/+0x24; load-map
record 0x1a8 with sky/load-sky/parts +0x10/+0x18c/+0x190; menu-init record
0x98 with scene/pack/top/count/font-block +0x18/+0x20/+0x2c/+0x30/+0x34.
Existing type comments and enums cover these fields. No new header layout
or signature correction is supported.

The candidate recovers all nineteen strings, uses LOAD_FILE_READ and
SCENE_DATA_MAP, removes redundant placement casts, replaces the target's
rounding-helper uses by actual arithmetic, and gives the function local
binding. Shared water/movie literals and the existing Align16Blocks helper
remain for other consumers. All literal bytes including terminators and
the local function symbol are audited. A failed private preparation removed
that shared helper; it is restored before every successful control and the
failed attempt remains in the receipt directory.

Three controls and twenty new source/float probes preserve all 36 nonselected
score rows and 39 emitted bodies, sizes, bindings and normalized data targets.
Eight generated data numbers move after cleanup, with full data fingerprints
unchanged. The already matched title drawing function remains zero. Exact
specimens, type/constructor witnesses, residual classification, input hashes
and all twenty-three objects are under `.private/pntc/title-boot-natural/`.
No guarded-only row or approximate source is activated.
