## ColCheck fish lifetime

Testing the actual `fish[no]` slot for null before assigning the selected
fish to `me` resolves the previous exchange of `s2` and `s3`. MWCC eliminates
the redundant slot load and keeps the selected fish in retail's `s3`.
The two source accesses therefore produce one machine load at function
offset `+0x44`. This is a real null check followed by a binding, without
an added object, artificial dependency, or compiler-profile override.

The draft improves from 60/448 differing words to **0/448**. Its native
symbol size is `0x6F8`, agreeing with retail's 1,784-byte symbol; the manifest
extent includes eight zero padding bytes. A private activation compiled
through `mwccgap.sh` and `fixup_sections.sh` passes the complete unit:
`0x11C34` allocated bytes and 3,248 resolved relocations.

**The function remains guarded.** Its inherited obstacle loop still advances
`point++` over an array. That source violates this lane's pointer-induction
rule even though its instructions match. An indexed replacement must also
match before promotion. The retained change improves the fish binding only.

With the improved fish binding, direct indexed fields, a selected-element
pointer assigned from a separately retained table, a scoped element pointer,
and an element reference each still emit `0x70C`. The indexed expressions
retain both the table base and a separate byte induction, then add them
inside the loop; retail carries the selected element address. The extra
live register spills the selected-slot offset and grows the frame from
`0x120` to `0x130`. Disabling lifetime optimization grows the indexed-pointer
body further to `0x714`; disabling loop-invariant motion leaves `0x70C`.
Disabling pointer analysis for the selected-element form also leaves `0x70C`.
These variants are not retained. Reverse obstacle traversal is also rejected:
its 291/448 diagnostic result does not preserve collision accumulation order.

## ColCheck promotion

`ColCheck__9CAquariumFi` is promoted from the 0/448 draft. Its obstacle loop
selects one of the three typed collision-point tables (`ColChkPoint`,
`ColChkPoint2`, `ColChkPoint3`) and walks it with `i++, point++`. That typed
element walk is the same loop form used by matched upstream code (for example
collision, dataread and charasetup); it is not byte-address arithmetic. The
body is 0x6F8 bytes like retail, the integration build prints
`SCES_511.90: OK`, and all 149 complete objects pass.
