## Native shadow compositor

`mgEndDrawShadow__FP10mgCTextureP10mgCTexture` is native. Its ALPHA members are
initialized in register field order (`a`, `b`, `c`, `d`, `fix`). This produces
the retail scheduling of the independent FIX byte store and low-byte masks.
The draft changes from 25/204 differing words (0x328 code) to zero; retail’s
extent is 0x330. The complete unit has zero byte or resolved-relocation
differences: 0x4DB8 checked bytes and 1,049 relocations.

The SDK `sceGsDBuff` declaration already present in `mglib.hpp` supplies the
correct layout. `mgBeginFrame` can address the named clear-colour bytes and
draw-frame fields directly while remaining exact. No shared header needs a
change, and the source-only byte-array redeclaration is unnecessary.

Direct access to the existing global draw-buffer and frame-texture objects
avoids hoisting redundant pointers for the three large drafts. The frame-end
routine samples frame ticks before lazy static initialization, scopes the
readback image after the drawing primitive, and validates sample x and y
bounds separately. It uses negated `<=` comparisons where retail `c.le.s`
branches also handle unordered floating values. The display slot is the
actual `disp[mgDBuffID]` array element. These are guarded behavioral/source
improvements; they do not qualify as native matches.

### Blockers and reconsideration triggers

- **Interrupt control:** `VSyncCallBack` needs the inline retail `sync; ei`
  epilogue. Reconsider only with a verified compiler/SDK intrinsic that emits
  those instructions from acceptable source; an external `EIntr` call does
  not provide the same object.
- **Shared TEX0 copy/layout:** the two framebuffer copies call the declared
  out-of-line `sceGsTex0::operator=`. Prior mglib notes establish that a local
  inline experiment removes the call but leaves direct-global-address
  formation differences for TEX1/CLAMP. Reconsider with a shared-header
  owner’s verified TEX0 assignment representation and complete mg_texture
  plus mglib validation. No header patch is proposed from this lane.
- **Framebuffer source/allocation:** `mgSetPkFrameBuffer` still retains the
  default-frame pointer in a saved register rather than retail’s `t3` across
  `GetScreenSize`; the frame-value copy and later global metadata accesses
  also differ. Reconsider with natural SDK assignment/type evidence that
  eliminates that lifetime/addressing difference. The unit’s native siblings
  remain exact under the typed declaration.
- **Initialization source structure:** `mgInit` has different saved-register
  and stack allocation, and its flattened DIMX packing loop does not reproduce
  retail’s loop nesting/unrolling and 32-bit shift operations. Reconsider with
  the original natural dither-table loop shape/type evidence; a helper mask
  does not resolve it.
- **Frame-end source/allocation:** the first remaining words are at +0x540:
  the depth mask and initial sample load use different temporaries and the
  commutative AND operand order differs. Other code is exact through +0x6BC;
  display indexing/addressing and packed register expressions differ from
  +0x6C0 onward. Reconsider with natural depth-buffer element typing and the
  SDK’s display-packing source expressions before any scheduling calibration.

GPR helper-history masks 0, 0x10 and 0x30 produce identical initial drafts in
this unit. The improved frame-end performance-meter floating calls already
match retail before the integer depth/display differences, so no verified
helper-history or floating-order profile row follows from this evidence.
