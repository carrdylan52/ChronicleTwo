## Source evidence

Both texture-group loops obtain their block lists through the inline
`CScene::GetTextureBlockNo` accessor (scenesnd.hpp) rather than calling
`mds_list_set.GetTextureBlockNo` directly. The accessor's return value is a
temporary, so the loop guard tests the call result in `v0` before the count
is copied to its saved register, as retail does at `+0x428` and `+0x6EC`.
Calling the member directly makes the guard read the copied count and
reverses that pair; it also exchanges the forward loop's count and byte
offset registers. title.cpp's matched draw routine uses the same accessor
for the same two-loop pattern.

The reverse loop names the element index (`count - i - 1`) and indexes
`texture_blocks` with it for both the drawn block and the water-block test,
as title.cpp does. A named pointer to the element gives the same instructions
but exchanges the count and element-address registers (six words).
